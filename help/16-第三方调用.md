第三方调用
==========

让别的程序指挥 WinSize 摆窗口，比如脚本、启动器、AI。

WinSize 常驻托盘时，会在本机开一个小 HTTP 服务。第三方发一条请求就能操作，不需要像命令行那样每次启动一个新进程。

5.x 曾有 `WinSize-Cli.exe`，6.0 起移除。命令行每次调用要启动解释器，实测约 200ms；HTTP 只是向已经在运行的进程发一条请求。旧的批处理、Quicker 动作改成一次请求即可。

## 服务一直在

服务随程序启动，托盘图标出现时就已经在监听。设置页只是它的一个页面，开不开设置页都不影响外部调用。

服务启动时会在程序目录写 `runtime.json`，里面是端口和令牌：

```json
{"app":"WinSize","version":"6.0.1","port":8790,"token":"……32 位十六进制……","pid":1234}
```

| 字段 | 用途 |
| --- | --- |
| `port` | 实际监听的端口，从 8790 起找空闲的，不要写死 |
| `token` | 放在请求头 `X-WinSize-Token`，或 URL 参数 `t=` |
| `pid` | 进程号，用来确认程序还活着 |

服务默认永不自动关闭（`[Server] IdleMs = 0`）。想让它空闲时关闭，可以改成毫秒值，例如 5 分钟：

```ini
[Server]
IdleMs = 300000
```

程序退出时会删除 `runtime.json`，避免外部程序连到已经关闭的端口。调用方要处理“文件不存在等于程序没在跑”。

## 常用接口

| 接口 | 作用 |
| --- | --- |
| `GET /api/windows` | 查看当前窗口：句柄、标题、矩形、屏幕号、能不能动 |
| `POST /api/apply` | 把窗口摆到指定位置。默认只预演，加 `commit=1` 才实际执行 |
| `POST /api/restore` | 撤销上一次 apply |

请求体是 `key=value&key=value`，不是 JSON。

### 看窗口

```bat
curl -s -H "X-WinSize-Token: <token>" "http://127.0.0.1:8790/api/windows?exe=chrome"
```

每条带 `hwnd`（下一步要用）、`rect`（窗外框）、`visibleRect`（肉眼看到的边界）、`monitor`（在哪块屏）、`operable`（0 表示不能动：在排除表里、工具窗或系统窗）。

`hwnd=0` 是特殊值，表示当前激活窗口。多数场景够用，不必先查。

### 摆窗口，先预演

```bat
curl -s -X POST -H "X-WinSize-Token: <token>" ^
  -d "hwnd=131072&target=layout:LeftTop" http://127.0.0.1:8790/api/apply
```

`target` 有两种写法：

| 写法 | 含义 |
| --- | --- |
| `layout:名字` | 用配置里已有的方案，推荐。名字见 `GET /api/layouts` |
| `rect:0\|0\|50sw\|100sh` | 直接给布局串，语法见 [03 布局方案](./03-布局方案.md) |

不加 `commit` 只计算、不修改，返回目标矩形并注明未执行。确认没问题再加 `commit=1`。

返回值里每条都有 `verdict`：

| verdict | 含义 | 怎么办 |
| --- | --- | --- |
| `ok` | 到位，偏差不超过 2 像素 | 完成 |
| `rounded` | 差 3~7 像素，取整或边框导致 | 当成功 |
| `clamped` | 尺寸被窗口顶住，明显小于目标 | 换更大的目标 |
| `blocked` | 几乎没动 | 多半是管理员权限窗口 |
| `maximized` | 窗口处于最大化，已按最大化处理 | 要精确摆放需先还原 |
| `partial` | 动了但没到位 | 把实际值报给用户，不要假装成功 |

结果要看 `actual`，也就是实际回读到的矩形，不能只看 `target`。

`clamped` 和 `blocked` 的区别是窗口有没有动。`clamped` 动了，但尺寸被最小尺寸顶住；`blocked` 完全没动。不要看到 `clamped` 就当成权限问题去建议用户提权。

### 批量

一条请求可以带多个窗口，最多 50 条，用重复的 `hwnd` 起头：

```
hwnd=111&target=layout:FullLeft&hwnd=222&target=layout:FullRight&commit=1
```

只要有一条参数错，整批一个窗口都不动，错误里会指出是第几条（`ops[n]`）。

### 改完配置让它生效

直接编辑 `Config.ini` 后，程序不会自己发现。发一条：

```bat
curl -s -X POST -H "X-WinSize-Token: <token>" http://127.0.0.1:<port>/api/reload
```

| 返回字段 | 说明 |
| --- | --- |
| `changes` | 生效后的布局数、按键数、正在运行的插件数 |
| `badLayouts` | 写坏的布局，含名字和原值。不为空就按名字去改 |
| `switched` | 这次被启停的插件，比如 `["+guides","-hover"]` |
| `pluginsReloaded` | 参数变了、被重新加载的插件 |
| `restartRequired` | 改了但要重启程序才生效的项。当前没有这类项，恒为空数组 |

重载不挪动任何窗口，也不恢复撤销记录。

没有 `/api/restart`。重启会当场断开连接，服务也不会自己再起来，需要用户手动操作。

### 校验配置

AI 写完 `Config.ini`，可以先检查一遍：

```bat
curl -s -X POST -H "X-WinSize-Token: <token>" ^
  --data-urlencode "text@Config.ini" http://127.0.0.1:8790/api/config/check
```

不带 `text` 就校验磁盘上的当前文件。返回：

```json
{"ok":false,"source":"text",
 "errors":[{"line":37,"section":"Layout","key":"LeftTop",
            "message":"格式应为 x|y|宽|高","format":"..."}],
 "stats":{"sections":9,"keys":23,"layouts":9,"keybindings":23}}
```

错误带行号，拿到就能直接改。校验失败也返回 200，因为请求本身是成功的。`ok:false` 表示文件有问题，不是请求写错了。

这个接口只读，不写文件，不改内存，可以反复调用。

## 出错时

`error` 永远是一个对象：

```json
{"ok":false,"error":{
  "code":"bad-layout",
  "message":"ops[0] 的布局名「LeftTp」不存在",
  "format":"布局名必须是 [Layout] 里已有的名字，或改用 rect:<布局串>",
  "options":["LeftTop","FullTop","…"],
  "example":"target=layout:LeftTop"
}}
```

常见 `code`：

| code | 含义 |
| --- | --- |
| `bad-request` | 参数形状不对 |
| `no-window` | 窗口已关闭 |
| `not-operable` | 该窗口不能动，在排除表里或是工具窗 |
| `bad-layout` | 方案名或布局串不对 |
| `too-many` | 超过 50 条 |
| `wrong-method` | HTTP 方法用错，比如对 `/api/apply` 用了 GET |
| `forbidden` | token 不对 |

## 各启动器怎么接

思路是读 `runtime.json`，然后发一次 POST。多数启动器支持“运行命令”，调 `curl` 即可。Win10 1803 起系统自带 `curl.exe`。

### Quicker

- “获取窗口信息”，句柄存到变量 `winid`。
- “运行或打开”，程序填 `curl.exe`，参数：

  ```
  -s -X POST -H "X-WinSize-Token: <token>" -d "hwnd={winid}&target=layout:LeftTop&commit=1" http://127.0.0.1:8790/api/apply
  ```

### uTools

```js
const rt = JSON.parse(require('fs').readFileSync('D:/WinSize/runtime.json', 'utf8'))
await fetch(`http://127.0.0.1:${rt.port}/api/apply`, {
  method: 'POST',
  headers: { 'X-WinSize-Token': rt.token, 'Content-Type': 'application/x-www-form-urlencoded' },
  body: 'hwnd=0&target=layout:LeftTop&commit=1'
})
```

### AutoHotkey

```ahk
req := ComObject("WinHttp.WinHttpRequest.5.1")
req.Open("POST", "http://127.0.0.1:8790/api/apply", false)
req.SetRequestHeader("X-WinSize-Token", token)
req.Send("hwnd=0&target=layout:LeftTop&commit=1")
```

## 安全边界

| 事实 | 含义 |
| --- | --- |
| 只绑 `127.0.0.1` | 局域网和外网都连不上 |
| `token` 是能力票据，不是身份认证 | 它挡的是浏览器里的其他网页偷偷向本机端口发请求，也就是 CSRF。能读 `runtime.json` 的本机程序也能读 `Config.ini`，别把它当权限隔离 |
| 重启后 token 会变 | 旧地址立即失效 |
| `apply` 默认只预演 | 写操作会影响用户正在用的窗口，所以默认不落地 |
| `restore` 只有一步 | 连续两次 apply 之后只能退回最近一次 |

`/api/config` 一类接口是给设置页用的，第三方不必碰。

## 让 AI 直接摆窗口

前面几节是给写脚本的人看的。如果你用的是带工具调用能力的大模型，比如 Claude、ChatGPT 的 Agent 模式、各类 AI 编程助手，不用自己写脚本，把技能包丢给它就行：

[skills/winsize/SKILL.md](https://github.com/dmscode/WinSize/tree/master/skills/winsize)

这是一份写给模型看的说明书，里面写清楚了：

- 开工前要确认什么：Node 版本、程序在跑、`runtime.json` 在哪。
- 每条命令的参数和返回。
- 布局串语法与常用写法。
- `verdict` 每个值的含义，没摆到位不等于失败。
- 出错时怎么读错误码，哪些情况重试也没用。
- 不要做的事，比如把 token 贴到公开地方。

### 怎么用

1. 确保 WinSize 正在运行，托盘有图标。
2. 把 `SKILL.md` 整个文件贴给模型，或者放进它的 skills / 知识库目录。
3. 直接说人话：“把 Chrome 放到左半屏，微信放到右上角”。

### 前提：发布包里带了 `cli/winsize.mjs`

模型不会手写 HTTP 请求，而是调用包里的小脚本：

```
<WinSize 目录>\cli\winsize.mjs
```

它负责读 `runtime.json`、带 token、转义中文和 `|`。这一步最容易出错，所以做成了脚本。

脚本需要 Node.js 18 以上。没有 Node 也能用，让模型直接发 HTTP，就是上面几节写的那样，只是中文标题需要自己做 URL 编码，容易出错。

脚本不放在技能包里，是因为它要读程序目录的 `runtime.json`。放在 `cli/` 下，才能在任何工作目录都被正确找到。技能包只放说明书，脚本跟着程序走。

### 常用命令

| 命令 | 做什么 |
| --- | --- |
| `status` | 看服务是否在跑、当前版本 |
| `windows` | 列出可操作的窗口和它们的 hwnd |
| `layouts` | 列出所有布局方案 |
| `apply` | 把一个窗口摆到某个位置 |
| `batch` | 一次摆多个窗口 |
| `save-layout` / `del-layout` | 存或删一个布局方案 |
| `reload` | 重载配置 |

摆一个窗口，用布局名字：

```
node cli/winsize.mjs apply --hwnd=123456 --layout=LeftTop --commit
```

也可以直接给矩形，跳过布局方案：

```
node cli/winsize.mjs apply --hwnd=123456 --rect="0|0|50sw|100sh" --commit
```

摆多个窗口用 `batch`，`--op` 可以重复，一次调用省掉重复启动：

```
node cli/winsize.mjs batch --op="hwnd=123456,target=layout:LeftTop" --op="hwnd=654321,target=layout:RightTop" --commit
```

不加 `--commit` 只预演，返回会说准备把窗口摆到哪里，实际不动。
