第三方调用
==========

让别的程序（脚本、启动器、AI）指挥 WinSize 摆窗口。

WinSize 常驻托盘时，可以在本机开一个小 HTTP 服务，第三方直接发请求即可——
**没有冷启动**，不像命令行那样每次调用都要起一个新进程。

> 5.x 曾有 `WinSize-Cli.exe`，6.0 起移除。命令行每次调用要启动解释器（实测约 200ms），
> 而 HTTP 只是向已在运行的进程发一条请求。旧的批处理、Quicker 动作改成一次请求即可。

## 第一步：把服务叫起来

服务**随程序启动，一直开着**，不需要任何额外操作：

> 托盘图标出现时，服务就已经在监听了。设置页只是它的一个页面，
> 开不开设置页都不影响外部调用。

服务启动时会在程序目录写 `runtime.json`，里面是端口与令牌：

```json
{"app":"WinSize","version":"6.0.0","port":8790,"token":"……32 位十六进制……","pid":1234}
```

| 字段 | 用途 |
| --- | --- |
| `port` | 实际监听的端口，从 8790 起找空闲的，**不要写死** |
| `token` | 放在请求头 `X-WinSize-Token`，或 URL 参数 `t=` |
| `pid` | 进程号，用来确认程序还活着 |

服务**永不自动关闭**（`[Server] IdleMs = 0` 是默认值）。想让它在没人用时收摊，
可以改成一个毫秒值，例如 5 分钟：

```ini
[Server]
IdleMs = 300000
```

> `runtime.json` 在程序退出时删除，避免外部程序连到一个已经关掉的端口。
> 所以调用方要处理"文件不存在 = 程序没在跑"。

## 三个常用接口

| 接口 | 作用 |
| --- | --- |
| `GET /api/windows` | 看现在有哪些窗口（句柄、标题、矩形、屏幕号、能不能动） |
| `POST /api/apply` | 把窗口摆到指定位置；**默认只预演**，加 `commit=1` 才真动 |
| `POST /api/restore` | 撤销上一次 apply |

请求体是 `key=value&key=value`（不是 JSON）。

### 看窗口

```bat
curl -s -H "X-WinSize-Token: <token>" "http://127.0.0.1:8790/api/windows?exe=chrome"
```

每条带 `hwnd`（下一步要用）、`rect`（窗外框）、`visibleRect`（肉眼看到的边界）、
`monitor`（在哪块屏）、`operable`（0 = 不能动：在排除表里 / 工具窗 / 系统窗）。

`hwnd=0` 是一个特殊值，表示**当前激活窗口**——多数场景够用，不必先查。

### 摆窗口（先预演）

```bat
curl -s -X POST -H "X-WinSize-Token: <token>" ^
  -d "hwnd=131072&target=layout:LeftTop" http://127.0.0.1:8790/api/apply
```

`target` 两种写法：

| 写法 | 含义 |
| --- | --- |
| `layout:名字` | 用配置里已有的方案（推荐，名字见 `GET /api/layouts`） |
| `rect:0\|0\|50sw\|100sh` | 直接给布局串（语法见 [03 布局方案](./03-布局方案.md)） |

**不加 `commit` 只算不改**，返回目标矩形并注明未执行。确认没问题再加 `commit=1`。

返回值里每条都有 `verdict`：

| verdict | 含义 | 该怎么办 |
| --- | --- | --- |
| `ok` | 到位（偏差 ≤2px） | 完成 |
| `rounded` | 差 3~7px（取整/边框） | 当成功 |
| `clamped` | 尺寸被窗口顶住，明显小于目标 | 换更大的目标 |
| `blocked` | 几乎没动 | 多半是管理员权限窗口 |
| `maximized` | 窗口处于最大化，已按最大化处理 | 要精确摆放需先还原 |
| `partial` | 动了但没到 | 把实际值报给用户，别假装成功 |

**不等于 `ok` 不是 bug**：请按 `actual`（实际回读到的矩形）判断结果，而不是 `target`。

`clamped` 与 `blocked` 的区别是**窗口有没有动**：`clamped` 动了但尺寸被最小尺寸限制顶住；
`blocked` 完全没动。别把前者当成权限问题去建议用户提权。

### 批量

一条请求可以带多个窗口（最多 50 条），用重复的 `hwnd` 起头：

```
hwnd=111&target=layout:FullLeft&hwnd=222&target=layout:FullRight&commit=1
```

**只要有一条参数错，整批一个窗口都不动**，错误里会指出是第几条（`ops[n]`）。

### 改完配置让它生效

直接编辑 `Config.ini` 之后程序不会自己发现，发一条：

```bat
curl -s -X POST -H "X-WinSize-Token: <token>" http://127.0.0.1:<port>/api/reload
```

| 返回字段 | 说明 |
| --- | --- |
| `changes` | 生效后的布局数、按键数、正在运行的插件数 |
| `badLayouts` | **写坏的布局**（名字 + 原值）。不为空就按名字去改 |
| `switched` | 这次被启停的插件，如 `["+guides","-hover"]` |
| `pluginsReloaded` | 参数变了、被重新加载的插件 |
| `restartRequired` | 改了但**要重启程序**才生效的项。当前没有这类项，恒为空数组 |

重载**不挪动任何窗口**，也不恢复撤销记录。

**没有 `/api/restart`**：重启会当场断开连接，服务也不会自己再起来。要重启请让用户手动操作。

### 校验配置（只读）

AI 写完 `Config.ini` 想先检查一遍：

```bat
curl -s -X POST -H "X-WinSize-Token: <token>" ^
  --data-urlencode "text@Config.ini" http://127.0.0.1:8790/api/config/check
```

不带 `text` 就校验磁盘上的当前文件。返回：

```json
{"ok":false,"source":"text",
 "errors":[{"line":37,"section":"Layout","key":"LeftTop",
            "message":"格式应为 x|y|宽|高","format":"..."}],
 "stats":{"sections":9,"keys":23,"layouts":9,"keybindings":23}}
```

**带行号**，所以拿到就能直接改。校验失败也返回 200——请求本身是成功的，
`ok:false` 表示"文件有问题"，与"请求写错了"是两件事。

它只读：不写文件、不改内存，可以反复调。

## 出错时

`error` 永远是一个对象：

```json
{"ok":false,"error":{
  "code":"bad-layout",
  "message":"ops[0] 的布局名「LeftTp」不存在",
  "format":"布局名必须是 [Layout] 里已有的名字，或改用 rect:<布局串>",
  "options":["LeftTop","FullTop","…"],
  "example":"target=layout:LeftTop"
}}
```

常见 `code`：

| code | 含义 |
| --- | --- |
| `bad-request` | 参数形状不对 |
| `no-window` | 窗口已关闭 |
| `not-operable` | 该窗口不能动（排除表 / 工具窗） |
| `bad-layout` | 方案名或布局串不对 |
| `too-many` | 超过 50 条 |
| `wrong-method` | HTTP 方法用错（比如对 `/api/apply` 用了 GET） |
| `forbidden` | token 不对 |

## 各启动器怎么接

原则：**读 `runtime.json` → 发一次 POST**。多数启动器支持「运行命令」，调 `curl` 即可
（Win10 1803 起系统自带 `curl.exe`）。

### Quicker

- 「获取窗口信息」→ 句柄存到变量 `winid`
- 「运行或打开」→ 程序 `curl.exe`，参数：

  ```
  -s -X POST -H "X-WinSize-Token: <token>" -d "hwnd={winid}&target=layout:LeftTop&commit=1" http://127.0.0.1:8790/api/apply
  ```

### uTools

```js
const rt = JSON.parse(require('fs').readFileSync('D:/WinSize/runtime.json', 'utf8'))
await fetch(`http://127.0.0.1:${rt.port}/api/apply`, {
  method: 'POST',
  headers: { 'X-WinSize-Token': rt.token, 'Content-Type': 'application/x-www-form-urlencoded' },
  body: 'hwnd=0&target=layout:LeftTop&commit=1'
})
```

### AutoHotkey

```ahk
req := ComObject("WinHttp.WinHttpRequest.5.1")
req.Open("POST", "http://127.0.0.1:8790/api/apply", false)
req.SetRequestHeader("X-WinSize-Token", token)
req.Send("hwnd=0&target=layout:LeftTop&commit=1")
```

## 安全边界

| 事实 | 含义 |
| --- | --- |
| 只绑 `127.0.0.1` | 局域网、外网都连不上 |
| `token` 是**能力票据**，不是身份认证 | 它挡的是"浏览器里的其他网页偷偷向本机端口发请求"（CSRF）。能读 `runtime.json` 的本机程序也能读 `Config.ini`，别把它当权限隔离 |
| 重启后 token 会变 | 旧地址立即失效 |
| `apply` 默认只预演 | 写操作会影响用户正在用的窗口，所以默认不落地 |
| `restore` 只有 1 步 | 连续两次 apply 之后只能退回最近一次 |

`/api/config` 一类接口是给设置页用的，第三方不必碰。

## 让 AI 直接摆窗口（技能包）

前面几节是"人写脚本"。如果你用的是带工具调用能力的大模型（Claude、ChatGPT 的 Agent 模式、
各类 AI 编程助手），**不用自己写脚本**——把这份技能包丢给它就行：

**[skills/winsize/SKILL.md](https://github.com/dmscode/WinSize/tree/master/skills/winsize)**

它是一份写给模型看的说明书，里面写清楚了：

- 开工前要先确认什么（Node 版本、程序在跑、`runtime.json` 在哪）；
- 每条命令的参数与返回；
- 布局串语法与常用写法；
- `verdict` 每个值的含义（"没摆到位"不等于"失败"）；
- 出错时怎么读错误码、哪些情况重试也没用；
- 绝对不要做的事（比如别把 token 贴到公开地方）。

### 怎么用

1. 确保 WinSize 正在运行（托盘有图标）；
2. 把 `SKILL.md` 整个文件内容贴给模型，或者放进它的 skills / 知识库目录；
3. 直接说人话："把 Chrome 放到左半屏，微信放到右上角"。

### 前提：发布包里带了 `cli/winsize.mjs`

模型不会手写 HTTP 请求，而是调用包里那个小脚本：

```
<WinSize 目录>\cli\winsize.mjs
```

它负责读 `runtime.json`、带 token、转义中文与 `|`——**这一步最容易出错，所以做成脚本**。

这个脚本需要 **Node.js 18 以上**。没有 Node 也能用，让模型直接发 HTTP（就是上面几节写的那样），
只是中文标题需要自己做 URL 编码，容易翻车。

> 为什么脚本不放在技能包里：它要读程序目录的 `runtime.json`，放在 `cli/` 下才能在任何工作目录
> 都被正确找到。技能包只放说明书，脚本跟着程序走。
