配置文件
========

所有设置都在 `Config.ini` 里，文件在 exe 同目录。它是纯文本，可以直接改，也可以用设置页改。设置页改的就是这个文件。

## 开始前

文件不存在时，程序用内置默认值运行：九个方案、九个按键、九个鼠标区都在。**但文件本身不会被重建**——之后从设置页保存会失败（没有可写的文件），所以别把"删掉配置"当成恢复出厂的正规做法，见 [17 常见问题](./17-常见问题.md)。

手改之后要重载。程序不会盯着文件看，改完在等待态按 `R`，或者点托盘菜单的“重载”。

文件要存成 UTF-8，带 BOM。Windows 记事本默认就是这个编码。存成 ANSI 会让中文路径变乱码，表现为排除规则突然不生效。

改之前建议复制一份 `Config.ini.bak`。程序在写入前也会自己生成一份。

## 哪些东西会存进来

| 会存 | 不会存 |
| --- | --- |
| 布局方案、按键、九宫格映射、托盘菜单 | 辅助线现在显不显示 |
| 排除列表 | 悬停激活现在跑不跑，只有“启动时是否自动跑”会存 |
| 插件开关与参数 | 窗口置顶状态 |
| 开机自启之外的偏好 | 上一次的撤销记录 |
| 窗口绑定的槽位 | — |

判断标准很简单：跨会话还有意义的东西才存。临时的开关状态只放在内存里，重启就回到初始值。

## 节一览

```ini
[Meta]          配置结构版本（程序维护，不用管）
[Help]          帮助页地址
[Plugins]       插件总开关
[Plugins.xxx]   各插件的私有参数
[Switch]        全局功能开关
[Layout]        布局方案
[Keys]          按键绑定
[QuickLayout]   九宫格到方案的映射
[Tray]          托盘菜单
[Exclusions]    窗口排除
[Server]        本地服务参数
```

顺序无所谓，节名不区分大小写。

## [Meta]

```ini
[Meta]
ConfigVersion = 1
UpdateLatest   = 6.0.2
UpdateDate     = 2026-11-20
UpdateCheckedAt = 2026-11-17 10:40
```

`ConfigVersion` 用来判断配置结构是否需要迁移，不要手改。

后三个 `Update*` 由设置页写入，程序只读，只用于托盘的新版本提示。不用手改，改错最多丢一次提示，不影响其它功能。

## [Help]

```ini
[Help]
Page = https://example.com/my-winSize-help
```

按 `H` 时打开的地址。不写这一节或留空时，用程序内置的默认值。默认值随版本走，这里不抄一遍，避免两处对不上。

可以改成自己的笔记、公司 wiki，或者本地文件：

```ini
Page = file:///D:/Docs/WinSize%E5%BF%AB%E6%8D%B7%E9%94%AE.md
```

## [Plugins]

```ini
[Plugins]
capsTip = 1
dragGrid = 1
guides = 1
winBind = 1
hover = 1
```

| 键 | 插件 | 写 0 的后果 |
| --- | --- | --- |
| `capsTip` | 大写提示 | 按 CapsLock 不再提示，恢复系统原生行为 |
| `dragGrid` | 拖拽调整 | `LAlt + 右键` 手势失效 |
| `guides` | 辅助线 | `G` 等键失效 |
| `winBind` | 窗口绑定 | 数字键失效，已存的槽位不再加载 |
| `hover` | 悬停激活 | `T` 失效 |

没列出的插件视为启用。想全部打开，把这个节清空即可。

关掉插件后，它提供的动作也会消失。如果 `[Keys]` 里还有键引用它，那个键按下会提示 `Error Action`，日志里会记一条“按键绑定无效”。

## [Plugins.xxx]

每个插件自己的参数，核心不解析，由插件读取。详见各功能文档：

| 节 | 参数 | 见 |
| --- | --- | --- |
| `[Plugins.DragGrid]` | 网格密度、透明度、顶部标题栏、右上角置顶 | [04](./04-鼠标手势.md) |
| `[Plugins.Guides]` | 线宽、颜色、透明度、缺口 | [10](./10-辅助线.md) |
| `[Plugins.Hover]` | 停留时长、启动时是否自动跑 | [11](./11-悬停激活.md) |
| `[Plugins.WinBind]` | 槽位表，程序自动写 | [09](./09-窗口绑定.md) |

`[Plugins.WinBind]` 长这样，不需要手写：

```ini
[Plugins.WinBind]
1 = 132416|D:\Apps\Zed\zed.exe|Zed|main.rs - Zed
```

格式是 `句柄|进程路径|窗口类|标题`。删掉某一行就等于解绑那个槽位。

## [Switch]

全局开关，`1` 开，`0` 关。可以只写要改的项，没写的保持默认。

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `logError` | 1 | 写 `Debug.log`。关掉后只记错误，不记普通信息 |
| `CapsTip` | 1 | 旧键，已下放为插件；值会迁移一次，保留仅为兼容 |
| `ShowTime` | 1 | 等待条显示当前时间，而不是 `WAITING` |
| `QuickLayout` | 1 | 鼠标手势总开关，控制九宫格和拖框 |
| `MultiDpi` | 1 | 混合 DPI 时跳过阴影补偿，见下 |
| `AutoCheckUpdate` | 1 | 打开设置页时检查更新。关掉后不自动查，托盘仍显示上次结果，设置页可手动检查 |
| `ForceResize` | 1 | 被应用自身的尺寸限制夹住时，绕过限制再压一次。关掉后停在应用允许的尺寸 |

关于 `MultiDpi`：各屏缩放比例不一致时，程序默认不去猜 DWM 阴影的厚度，直接按像素算，这样位置更准。
各屏缩放一致时仍会正常补偿。除非你遇到窗口总是偏几像素，否则不用动它。

关于 `ForceResize`：有些应用会声明自己的最小尺寸（比如不小于 1000×750），摆到更小的目标时窗口会停在那儿。
开着这个开关，程序会再压一次、多数情况能真的到目标尺寸（`/api/apply` 的结果里 `forced=1` 就是这种）。
关掉后只按正常方式摆一次，被限制就停在应用允许的尺寸——代价是有些布局只能"尽量"，好处是绝不跟应用抢尺寸。

启动时如果 `[Switch]` 缺了某个键，程序会自动补上默认值。它只补开关，不补布局和按键，因为删掉一个布局是明确的意图，补回去等于篡改。

## [Layout]

```ini
[Layout]
LeftTop     = 0|0|50sw|50sh
MyWide      = 0|0|70sw|100sh
```

名字在等号左边，规则在右边。写法见 [03 布局方案](./03-布局方案.md)。

这一节是整体覆盖。文件里有 `[Layout]`，内置的九个默认方案就全部失效。想保留默认值，要把它们一起写进来。

## [Keys]

```ini
[Keys]
Q = Layout|LeftTop
P = Pin
1 = WinBind|1
```

格式是 `键 = 动作|参数`。同样是整体覆盖。详见 [05 按键绑定](./05-按键绑定.md)。

## [Plugins.WindowSwitch]

窗口切换插件的两个全局快捷键、匹配标准与切换方式。整节删掉也能用，等于全部取默认值；在设置页里改是同一份配置。

```ini
[Plugins.WindowSwitch]
; 下一个 / 反向，写法是"修饰键 + 键名"：<! 左Alt、>! 右Alt、<^ 左Ctrl、<+ 左Shift
chord = <!`
; 修饰键顺序建议 Ctrl→Alt→Shift→Win（写成别的顺序也能用，读盘时会归一）
chordReverse = <!<+`
; 匹配标准：process（同进程）/ program（同程序）/ class（同程序 + 同窗口类）
match = class
; 切换方式：cycle（轮转）/ pair（仅最近两个）
mode = cycle
; 连按间隔（毫秒）：这段时间内继续按算同一轮，超过就重新开始
cooldownMs = 800
```

键名不合法、缺修饰键、或这个组合被别的程序占用时，程序只记一条日志并跳过这两个键，其它功能不受影响。设置页里这两项是"按键点选"控件，选完键盘上方立刻显示人类可读的标签（如「左 Alt + 反引号」），存回去仍是上面这种 AHK 写法。Windows 不提供可靠的占用查询，所以这里不做"冲突提示"——真被占了，表现为对方那个功能失灵。

## [QuickLayout]

九宫格的九个格子各对应哪个方案：

```ini
[QuickLayout]
1 = LeftTop
2 = FullTop
...
```

多显示器还能写两位编号，`21` 表示 2 号屏左上。查找顺序见 [04](./04-鼠标手势.md)。

## [Tray]

托盘菜单，行的顺序就是菜单顺序：

```ini
[Tray]
1 = cmd:settings
2 = -
3 = act:guides
4 = act:hover
5 = act:pin
6 = -
7 = cmd:reload
8 = cmd:restart
9 = cmd:help
10 = cmd:openLog
11 = -
12 = cmd:exit
```

| 写法 | 含义 |
| --- | --- |
| `-` | 分隔线 |
| `cmd:xxx` | 内建命令 |
| `act:动作\|参数` | 任意已注册动作 |

“设置”和“退出”必填，删了会被自动补回。详见 [13 托盘菜单](./13-托盘菜单.md)。

## [Exclusions]

窗口排除规则。默认是空节，节在，但一条规则都没有。用 `U` 键排除时程序往里写：

```ini
[Exclusions]
1 = D:\Program Files\Microsoft VS Code\Code.exe|Chrome_WidgetWin_1
```

格式是 `进程|窗口类`，两段都可以留空。详见 [07 窗口排除](./07-窗口排除.md)。

## [Server]

```ini
[Server]
IdleMs = 0
```

本地 HTTP 服务的空闲时长，单位毫秒。默认 `0` 表示永不关闭，程序一启动就监听，AI 或脚本随时能调用。想让它在没人用时关闭，写 `300000`，也就是 5 分钟。详见 [16 第三方调用](./16-第三方调用.md)。

## 手改出错会怎样

| 错误 | 后果 |
| --- | --- |
| 布局规则写坏 | 按到那个方案时提示 `Error Action`；按 `R` 重载时提示 `Bad Layout`，日志里有方案名和原值 |
| 按键引用了不存在的动作 | 那个键提示 `Error Action`，日志里有键名和原因 |
| 整个节写坏，比如少了 `[` | 该节读不到：`[Switch]` 逐键回默认值；`[Layout]` / `[Keys]` / `[QuickLayout]` 会**变成空表**（等于那部分功能全失效），不会回默认 |
| 存成 ANSI 编码 | 中文路径乱码，排除规则失效 |

日志在 exe 同目录的 `Debug.log`，托盘菜单的“打开日志”可以直接打开。遇到按了没反应，先看它。
